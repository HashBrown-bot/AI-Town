# AI-Town 使用体验与模拟升级

这一轮已将首页重做为地图与居民侧栏，修复居民移动、模拟时间、状态保存和请求等待中的主要问题。改动保留现有居民、对话、经济和分析功能。

## 已完成

- 导航从十个并列入口整理为「小镇、居民、对话、总览」，六个工具放入「更多」。使用更直接的中文名称。
- 首页提供居民姓名、职业、行动搜索，移动中/需关注筛选，简要状态卡、完整档案入口及最新对话/事件。侧栏可收起。
- 使用统一的深色背景、薄荷绿重点色、清晰留白和字号；手机采用上下布局，桌面采用左右布局。
- 原逻辑每秒走 speed × 2.2 像素；现在每 200ms 走 speed × 6 像素，同一 speed 下逻辑移动速度约提高 13.6 倍。画布插值显示连续位置。
- 模拟时钟、需求和行动每步都推进 1 分钟，保持 1× 下每秒推进 5 个模拟分钟。暂停、2×、5× 保留；暂停后继续恢复原倍速。
- 修复快进一小时跨午夜不增加天数、午夜被识别为上午 10 点、行动直接修改旧状态、快速移动越过目标等问题。
- 地图动画使用稳定循环，不随居民更新重新生成粒子；适配窗口大小与 Retina 分辨率。拖动使用指针捕获，拖动后不会误选居民，支持触屏和键盘。
- 自动对话的触发移出 React 状态更新函数，用最新处理器引用读取当前时钟与事件；保留 15 秒真实时间请求间隔，防止倍速放大 AI 请求。
- 对话请求 12 秒超时后使用现有回退内容，其他 AI 请求 20 秒超时。第一句立即显示，后续播放时间缩短。
- 大型本地状态每秒最多保存一次，离开页面或卸载时保存最新状态。捕获存储异常，避免存储失败中断模拟。
- 非首页面板与导出弹窗按需加载；开发 HUD 通过 ?debug=1 开启。
- 增加可选 VITE_DISABLE_CLOUD_SYNC=true 本地隔离模式。默认仍然云同步；这一选项必须在构建/启动前配置。

## 验证

- TypeScript 检查通过，生产构建通过。
- 8 项回归测试通过：跨天、时钟步长、移动速度、目标边界、旧状态不可变、对话驻足、工资结算和插值边界。
- 浏览器验证：居民搜索与简卡、完整档案跳转、动态侧栏、全部六个工具页、暂停后恢复 5×、24 次小时快进正确跨天。
- 1440×900 桌面与 390×844 手机布局检查完成；手机无横向溢出。
- 完整本地 Express + Vite 应用与离线对话接口验证通过，接口返回 HTTP 200 和 4 句对话。
- 使用同一组依赖比较原始 main 与新代码，正常云同步配置下首页 JS 从 1169.93 kB 降至 950.25 kB（约 -19%），gzip 从 346.18 kB 降至 294.14 kB（约 -15%）。这不是实际首屏耗时或 FPS 测量。
- 本地验证未使用真实 Gemini 凭据。实际模型延迟、配额和部署环境的端到端云同步需要线上验证。
- 需求、行动完成和工资现在与时钟同步，生活节奏比旧版更快，应结合较长时间的线上体验调整平衡。

## 下一轮应优先处理

1. **身份与数据隔离。** 当前 firestore.rules 的业务集合允许无需登录的读取和符合字段要求的写入；simulation_state/current 也是全局共享。应增加登录与用户/小镇所属关系，并让一个权威模拟实例负责推进世界，避免多个浏览器互相覆盖。此项涉及 Firebase 数据结构和部署迁移，不能只修改 GitHub 规则文件就算完成。
2. **AI 服务调度。** server.ts 的 AI 接口没有应用级鉴权或调用者限流；当前配额数字和模型名称写死。应增加用户级限流、请求去重、后台队列、可配置模型和真实用量指标。
3. **提示词与回退透明度。** 对话请求发送完整居民对象，长期记忆累积会增大传输；应裁剪为相关记忆和必要人格字段。界面应明确标记模型生成与规则回退，避免把示例或回退当作真实 AI 结果。
4. **二级页面的信息整理。** 居民档案、经济和情报页仍有大量专业指标。建议先展示状态摘要，再由用户展开需求、关系、决策和诊断详情，并逐页统一到新视觉规范。
5. **更大规模的模拟。** 目前针对现有 7 位居民做了体验修复；大量居民应进一步使用空间索引、独立模拟 Worker 和地图静态图层缓存。需要基于实际帧率与耗时测量推进。

## 本地运行

项目保留原有 Bun 依赖锁文件：

```sh
bun install
bun run dev
bun run lint
bun run test
bun run build
```

测试脚本需要 Node.js，当前验证使用 Node.js 24.19.0。开发服务器提供端口 3000 的完整应用。需要隔离云数据时在 .env.local 中设置 VITE_DISABLE_CLOUD_SYNC=true；需要真实 Gemini 内容时使用已有的 GEMINI_API_KEY 配置。

本轮不涉及 GitHub 项目权限变更。代码在独立分支中提交，合并 PR 后再按现有流程部署。
